# Pulsecheck

Веб-приложение для проверки скорости загрузки изображения. Пользователь
указывает URL и количество попыток, сервер выполняет загрузки последовательно, а интерфейс в
реальном времени показывает очередь и результат каждого запроса в терминале

После завершения итоговый отчёт и одна копия скачанного изображения сохраняются
в SQLite. На странице «Аналитика» можно сравнивать предыдущие измерения.

## Стек

- React 19 и TypeScript;
- Vite;
- `react-hook-form` и Zod для формы и валидации URL;
- Express и TypeScript;
- встроенный модуль Node.js `node:sqlite`;
- npm workspaces для организации монорепозитория.

Сторонний сервер базы данных не требуется. SQLite хранится в локальном файле
`data/speed-tests.db` и создаётся автоматически при первом запуске API.

## Требования

- Node.js 22.5 или новее: эта версия содержит `node:sqlite`;
- npm 10 или новее.

Проект проверен на Node.js 24.

## Установка и запуск

Установить зависимости всех workspaces:

```bash
npm install
```

Запустить API и React-приложение одной командой:

```bash
npm run dev
```

После запуска:

- интерфейс: `http://localhost:5173`;
- API: `http://localhost:4000`;
- проверка API: `http://localhost:4000/api/health`.

Vite перенаправляет запросы `/api` на Express, поэтому дополнительная настройка
CORS в режиме разработки не нужна.

## Проверка и production-сборка

```bash
npm run typecheck
npm run build
```

Запуск скомпилированного API:

```bash
npm start
```

Собранный React-клиент находится в `apps/web/dist`. В production его можно
раздавать через Nginx или другой статический сервер, направляя `/api` на порт
Express.

## Как проходит тест

1. Форма проверяет URL через Zod. Допускаются только адреса `http://` и
   `https://`.
2. Поле количества попыток хранится в форме как строка, затем Zod преобразует
   его в число и проверяет диапазон от 1 до 50. Значение по умолчанию — 10.
3. React отправляет `POST /api/tests` с URL и количеством попыток.
4. Express повторно валидирует оба значения и выполняет загрузки строго
   последовательно.
5. Ответ API имеет формат NDJSON: сервер отправляет отдельную JSON-строку при
   старте и после каждого запроса.
6. React читает поток через `ReadableStream` и сразу обновляет терминал.
7. После последнего запроса API рассчитывает статистику и записывает отчёт вместе
   с изображением в SQLite.
8. Финальное событие содержит ID записи и итоговые показатели.

До чтения тела каждого ответа проверяется заголовок `Content-Type`. Если он не
начинается с `image/`, тест прекращается с сообщением «Указанная ссылка не
является картинкой.». Сообщение появляется в центре экрана и плавно исчезает
через две секунды. Запись в SQLite выполняется только после успешного
завершения всех попыток, поэтому ошибочный или незавершённый тест в историю не
попадает.

Потоковый HTTP-ответ выбран вместо WebSocket, потому что коммуникация здесь
однонаправленная и ограничена временем одного теста. Это уменьшает количество
кода и не требует отдельного управления соединением.

## Собираемая статистика

Для каждого запроса сохраняются:

- фактический объём ответа;
- полное время загрузки;
- скорость в битах в секунду;
- TTFB — время до получения заголовков и начала ответа.

Итоговый отчёт содержит:

- общий объём и суммарное время;
- среднее, медианное, минимальное и максимальное время;
- стандартное отклонение времени;
- среднюю, минимальную и максимальную скорость;
- диапазон скорости;
- средний, минимальный и максимальный TTFB.

Объём автоматически форматируется как `B`, `KB`, `MB`, `GB` или `TB`.
Скорость отображается по принятой для сетей практике: `bit/s`, `Kbit/s`,
`Mbit/s`, `Gbit/s` или `Tbit/s`. Используются десятичные единицы SI.

Продолжительность также форматируется автоматически: значения меньше секунды
показываются в миллисекундах, затем используются секунды, минуты и часы.
Последний компонент времени содержит два знака после точки. Используется
стандартная запись длительности: `840.25 ms`, `12.45 s`, `02:05.27`
(`MM:SS.ss`) и `01:12:05.27` (`HH:MM:SS.ss`). В SQLite время
всегда хранится в миллисекундах, поэтому форматирование не влияет на точность
расчётов.

## Хранение изображения

Во время первого запроса тело ответа собирается в `Buffer`. Этот же буфер
используется для подсчёта размера и записывается в колонку SQLite типа `BLOB`.
Остальные девять ответов участвуют в измерениях, но повторно в базе не
сохраняются.

Изображение отдаётся через `GET /api/tests/:id/image` с исходным
`Content-Type`. Список аналитики не включает BLOB, поэтому загрузка таблицы не
передаёт все изображения одним большим JSON-ответом — браузер запрашивает
превью отдельно.

## API

### `POST /api/tests`

Тело запроса:

```json
{ "url": "https://example.com/image.jpg", "attempts": 10 }
```

Ответ — поток `application/x-ndjson`. Возможные события:

```text
{"type":"started","total":10,"url":"..."}
{"type":"request-started","number":1}
{"type":"request-complete","result":{...}}
{"type":"complete","test":{"id":1,"summary":{...}}}
```

### `GET /api/tests`

Возвращает историю отчётов от новых к старым без содержимого BLOB.

### `GET /api/tests/:id/image`

Возвращает сохранённое изображение.

### `DELETE /api/tests/:id`

Удаляет отчёт и сохранённое изображение из SQLite. Кнопка удаления находится в
таблице аналитики. Кнопка «Повторить» открывает форму с URL и количеством
попыток из выбранного отчёта.

## Docker

Собрать и запустить приложение:

```bash
docker compose up --build
```

После сборки интерфейс и API доступны на `http://localhost:4000`. Именованный
volume `pulsecheck-data` хранит SQLite между перезапусками контейнера.

Остановить контейнер:

```bash
docker compose down
```

## CLI-версия
